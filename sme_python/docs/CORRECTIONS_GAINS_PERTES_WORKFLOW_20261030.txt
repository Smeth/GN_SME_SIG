L20-01 — P1 confirmé — validation prématurée de transactions par le workflow
Emplacement : src/sme_gend/services/workflow_task_service.py:43.
Cause : _ensure_table exécutait le DDL de création même lorsque workflow_task
existait déjà. Un CREATE TABLE peut implicitement terminer la transaction active.
Trois reproductions natives avant correction : lire, créer ou résoudre une tâche
dans une transaction contenant une autre écriture, puis lever une exception ;
l'écriture antérieure persistait au lieu d'être annulée. Risque : opérations
métier partielles et sauvegardes/annulations qui ne correspondent plus à la demande.
Référence primaire : https://docs.oracle.com/cd/E17952_01/mysql-8.0-en/implicit-commit.html
Correction : vérification non mutatrice de présence, cache par instance du
service, aucune exécution DDL si la table existe. Table absente pendant une
transaction gérée : erreur explicite sans création. Initialisation autonome
historique conservée hors transaction active, avec verrou d'initialisation et
contrôle de l'état transactionnel de la connexion avant DDL. Schéma SQL inchangé.
Validation : trois régressions natives d'annulation, table absente et création
autonome, plus deux preuves workflow entre processus indépendants.
