ÉTAT RÉEL DE LA VALIDATION

L'utilisateur a confirmé ne pas avoir accès aux PC de travail actuellement.
Le chemin UNC exact et les lettres des lecteurs sur ces postes ne sont pas
disponibles. Sur le poste accessible : Get-SmbMapping et Win32_LogicalDisk
n'affichent aucun lecteur réseau ; aucun partage non système n'est listé.
Get-SmbConnection est inaccessible via CIM : son absence de résultat ne prouve
donc pas l'absence de toute connexion SMB.

Les essais sur le partage de travail et la synchronisation de l'application
entre deux vrais postes n'ont PAS été exécutés. Aucun résultat local ne les
remplace. Aucun serveur, pare-feu, droit, lecteur mappé ou profil MySQL n'a été
modifié pour créer artificiellement un environnement réseau.

Un kit autonome est fourni :
  scripts/Test-ImpressionSmb.ps1
  tests/manual/Test-ImpressionSmb.Local.ps1  (répétition locale du kit)

Le script principal utilise Windows PowerShell 5.1, sans Python ni accès MySQL.
Il résout une lettre de lecteur par WNetGetUniversalName vers le chemin UNC.
Des lettres différentes peuvent donc être utilisées sur les deux postes.
Les identifiants Windows déjà ouverts sont utilisés, sans demander ni enregistrer
de mot de passe. Le kit ne met pas à jour l'application.

COMMENT LANCER SUR LES PC DE TRAVAIL

1. Copier Test-ImpressionSmb.ps1 sur les deux postes, dans un dossier accessible
   à l'utilisateur. Ouvrir PowerShell dans ce dossier, avec le compte Windows
   qui utilise habituellement le partage. Ne pas changer de compte par élévation
   simplement pour retrouver les lecteurs d'une autre session Windows.

2. Sur le poste A, lancer en remplaçant Z:\Photos par le dossier réseau choisi :

   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-ImpressionSmb.ps1 -Role Start -Path 'Z:\Photos'

   Un sous-dossier neuf impression_smb_validation_<UUID> est créé. La console
   affiche SESSION_FOLDER= suivi de son chemin UNC. Le poste A attend le poste B.
   Les fichiers existants de l'application ne sont ni remplacés ni supprimés.

3. Pendant cette attente, sur le poste B, lancer :

   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-ImpressionSmb.ps1 -Role Join -SessionFolder '\\serveur\partage\Photos\impression_smb_validation_<UUID>'

   Remplacer le chemin par celui affiché par A. Pour tester explicitement la
   lettre différente sur B, on peut utiliser le chemin équivalent, par exemple :

   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-ImpressionSmb.ps1 -Role Join -SessionFolder 'P:\Photos\impression_smb_validation_<UUID>'

   Les deux chemins doivent viser le même sous-dossier UUID. Le script compare
   l'identité de session et la racine UNC résolue ; il refuse les messages anciens
   et les racines différentes. Le délai est de 180 secondes par phase ; l'option
   -TimeoutSeconds permet de le choisir entre 1 et 600 secondes.

4. Consulter a.result.json dans ce sous-dossier, ou lancer :

   powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\Test-ImpressionSmb.ps1 -Role Report -SessionFolder '<chemin de la session>'

   Ne pas ajouter -AllowLocalSelfTest aux essais réels. Cette option est réservée
   à la répétition locale et empêche de déclarer les vrais postes/SMB validés.

L'autorisation d'exécution des commandes ci-dessus est limitée au processus lancé.
Aucune politique Windows globale n'est modifiée. Si une politique de l'entreprise
bloque toujours le script, utiliser une exécution approuvée/signée par son
administrateur ; le kit ne modifie ni cette politique ni les réglages du poste.

CE QUE LE KIT MESURE

- Création, écriture, lecture et publication de fichiers dans le seul sous-dossier
  neuf de validation, avec l'utilisateur de chaque poste.
- Refus d'un verrou de plage d'octets détenu par l'autre participant, dans les
  deux sens, puis acquisition après libération du verrou.
- Remplacement d'un fichier créé par l'autre participant, dans les deux sens.
  Cela aide à repérer des droits de remplacement différents des seuls droits
  de création/lecture dans un dossier.
- Cinquante publications atomiques par MoveFileExW pendant les lectures de B ;
  contrôles de l'identifiant, de la séquence et du contenu complet. Une erreur
  de contenu/JSON échoue ; elle n'est pas remplacée par un résultat fictif.
- Observation du dialecte SMB quand Get-SmbConnection est accessible pour ce
  serveur et ce partage. Une impossibilité d'observer le dialecte reste explicite.
- Vérification que les deux noms de postes Windows diffèrent, sans les conserver
  en clair : un hachage lié à la session est utilisé. Deux processus sur le même
  poste ne peuvent pas passer pour deux postes dans le mode normal.

Le diagnostic réessaie les contentions temporaires connues de lecture/renommage
pendant 500 ms maximum par opération. Les codes et nombres de reprises sont
publiés dans RenameRetriesA/B, ReadRetriesB et RetryCodesA/B. Une erreur durable
ou un autre code provoque un échec. Ces reprises appartiennent AU DIAGNOSTIC :
elles n'ajoutent aucun mécanisme de réessai aux services Python de l'application.
Des compteurs non nuls doivent être examinés avant de conclure à la robustesse
de l'application pendant des lectures/exportations de photos concurrentes.

Le temps PublicationRoundtripMilliseconds comprend la sérialisation et les pauses
du protocole ; ce n'est pas un benchmark du débit SMB ou de la rapidité métier.

COMMENT INTERPRÉTER LES RÉSULTATS

SMB_FILE_CHECKS_PASSED : les primitives de fichier ont passé entre deux noms
de postes distincts via UNC et le dialecte SMB a été observé des deux côtés.
Cela ne valide pas les transactions MySQL ou l'ensemble de l'application.

UNC_FILE_CHECKS_PASSED : les primitives ont passé entre les deux postes via UNC,
mais le protocole SMB n'est pas observable des deux côtés. Le champ
SmbFileChecksValidated reste false ; UncFileChecksValidated est true.

LOCAL_REHEARSAL_PASSED : répétition locale explicitement activée. Elle ne valide
ni le réseau de travail ni deux vrais postes. Les champs réseau restent false.

VALIDATION_INCOMPLETE : échec de précondition, d'accès, de protocole ou de délai.
Le stade et le code natif sont conservés. Une erreur d'autorisation ne devient
pas une prétendue réussite du partage. Relancer une nouvelle session après examen,
sans réutiliser une session interrompue ou ses marqueurs.

MySQLApplicationSyncValidated reste toujours false dans ce script : il n'ouvre
aucune connexion SQL et n'appelle pas les flux métier Python.
