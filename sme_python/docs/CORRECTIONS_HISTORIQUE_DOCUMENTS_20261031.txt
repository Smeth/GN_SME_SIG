Limites et validation restante
- Les anciennes traces absentes, noms tronqués ou destinations temporaires ne sont
  pas réparés rétroactivement : aucune preuve ne permet de recréer une génération
  passée ou d'inventer son auteur. Les anciens journaux n'ont pas été modifiés.
- Le mois SME décrit la période des données, pas la date de génération. Choisir
  toutes les périodes pour retrouver les attestations qui n'avaient pas de mois.
  Les nouveaux libellés et la recherche de date rendent cette distinction explicite.
- Un fichier généré et son journal SQL ne forment pas une transaction distribuée.
  Si la confirmation MySQL manque, le fichier est conservé et l'erreur signalée.
  Un miroir hors ligne éventuel n'est pas assimilé à une entrée centrale confirmée.
- Les vrais PC/SMB ne sont pas disponibles. Détection locale de conflit, transactions,
  deux clients SQL et réactions Qt contrôlées ne remplacent pas une recette réseau.
- Tous les postes devront utiliser les corrections pour émettre les nouvelles
  notifications. Les anciens clients non modifiés nécessitent Actualiser.
- Recette Word/LibreOffice/imprimante physique et rendu de tous les gabarits réels
  non exécutés. Un PDF natif synthétique a été créé ; pas d'affirmation de validation
  exhaustive de mise en page. Les aperçus Word temporaires explicitement ouverts
  conservent leurs générations documentaires existantes.
- Les autres actions métier restent dans leurs journaux dédiés. Les exports CSV
  utilitaires de chaque écran n'ont pas tous été transformés en types de documents.
  Pas d'affirmation que l'application entière est sans bugs.
